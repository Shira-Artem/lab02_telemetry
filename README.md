# Лабораторная работа № 2. Сбор и анализ игровой телеметрии

Дисциплина «Игровой искусственный интеллект». Цель — собрать события игровых сессий, сохранить их в SQLite, вычислить поведенческие метрики и показать результат на дашборде. Проект основан на [шаблоне преподавателя](https://github.com/kolesnikov-vstu-gameai/lab02-telemetry), адаптирован для самостоятельной реализации без Unity и внешней инфраструктуры. Все демонстрационные данные синтетические.

## Технологии и архитектура

Python 3.11+ · FastAPI · SQLite · pandas · matplotlib · Streamlit · pytest.

`client/python_logger.py` генерирует события, записывает JSONL и при необходимости отправляет пакеты в `POST /events`. FastAPI проверяет схему и сохраняет данные в `data/telemetry.db`. `analysis/analyze.py` читает SQLite, считает четыре метрики и сохраняет графики в `results/`. `dashboard/app.py` читает ту же БД и строит интерактивные графики с фильтром уровня, подсказками при наведении и кнопкой обновления данных. Тема Streamlit задана в `.streamlit/config.toml`.

| Путь | Назначение |
|---|---|
| `client/python_logger.py` | Логгер и воспроизводимый генератор сессий |
| `server/app.py` | HTTP API, валидация, SQLite |
| `analysis/analyze.py` | Метрики и PNG-графики |
| `dashboard/app.py` | Дашборд на русском языке |
| `data/telemetry.db` | Демонстрационная БД с 40 сессиями |
| `docs/event_schema.md` | Формат событий и правила API |
| `docs/report.md` | Черновик отчёта и выводы |
| `tests/` | Тесты метрик и потока данных |

## Определения метрик

1. **Длительность сессии** — разность между первым `session_start` и первым следующим за ним `session_end` в одной сессии. Сессии без пары исключаются; выводятся медиана и гистограмма.
2. **D1 retention** — доля уникальных игроков, у которых есть `session_start` на следующий календарный день UTC после первого `session_start`. Повторные сессии в один день и возврат лишь через два дня не засчитываются.
3. **Heatmap смертей** — двумерная гистограмма координат `(x, y)` событий `death`, отдельно для каждого уровня. Сетка 10 × 10 охватывает игровое поле 0–100 по обеим осям.
4. **Воронка конверсии** — число сессий, достигших последовательно `session_start → checkpoint → level_complete` на том же уровне. Проценты считаются относительно числа стартовавших сессий; итоговая конверсия — завершившие / стартовавшие. Повторные события в одной сессии не увеличивают счётчик.

При фильтрации дашборда все метрики рассчитываются заново по событиям выбранного уровня. Пустые данные дают нулевые доли и пустые графики.

## Запуск в Windows PowerShell

Команды выполняются из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m client.python_logger --simulate 40 --seed 42
.\.venv\Scripts\python.exe -m analysis.analyze
.\.venv\Scripts\python.exe -m pytest -q
```

Последняя команда генерации пересоздаёт синтетические записи в SQLite и `data/events.jsonl` с тем же seed; другие записи в БД сохраняются. Для другого набора задайте `--seed` и число сессий от 30 до 50. JSONL создаётся локально и не включается в Git, так как те же данные можно воспроизвести.

Сервер и дашборд запускаются в двух отдельных окнах PowerShell:

```powershell
.\.venv\Scripts\python.exe -m uvicorn server.app:app --reload
```

```powershell
.\.venv\Scripts\python.exe -m streamlit run dashboard/app.py
```

Сервер доступен на `http://127.0.0.1:8000/docs`, дашборд — на `http://localhost:8501`. Для демонстрации отправки через HTTP при работающем сервере: `.\.venv\Scripts\python.exe -m client.python_logger --simulate 40 --seed 42 --http`. При штатной генерации без `--http` данные записываются в SQLite непосредственно, поэтому для первого запуска сервер не нужен.

## Результаты и интерпретация

При генерации с `--simulate 40 --seed 42` в SQLite сохранены **199 событий, 40 сессий и 22 игрока**. Медианная длительность — **297,5 с**, D1 retention — **36,4%**. Воронка: **40 → 31 → 23** сессии (100% → 77,5% → 57,5%). Аналитический скрипт сохраняет `session_length.png`, `conversion_funnel.png`, а также `death_heatmap_L1.png`, `death_heatmap_L2.png`, `death_heatmap_L3.png` в `results/`. По синтетическому набору 8 из 31 сессии с чекпоинтом не завершили уровень; это демонстрирует, как обнаруживать потери между этапами. Числа иллюстрируют работу пайплайна, а не поведение реальных игроков. Подробности — в [черновике отчёта](docs/report.md).
